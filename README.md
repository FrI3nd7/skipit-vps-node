## 💡 О проекте

**SkipIt Tool** — это интерактивная консольная панель (TUI) и набор инструментов на Bash для развертывания, защиты и администрирования VPS-серверов.

Инструмент разворачивает всю инфраструктуру Remnawave: **ноду**, **панель управления** и **страницу подписки** — по отдельности, парой или всё вместе на одном сервере.

Забудьте про рутину:
* 🐳 **Никакого ручного ковыряния в Docker Compose** — скрипт сам развернёт оптимизированную связку с Alpine Nginx.
* 🌐 **Сертификаты без головной боли** — Let's Encrypt, ZeroSSL или Cloudflare DNS, автоматическое продление без обрыва VPN.
* 🔑 **Панель настраивает себя сама** — администратор и API-токен создаются автоматически, вставлять вручную ничего не нужно.
* 🤖 **Нода заводится в панели сама** — профиль с ключами REALITY, сама нода и хост Self-steal (TCP) создаются через API, ходить в браузер не нужно.
* 💾 **Бэкап в Telegram** — база панели со всеми подписчиками и её файлы приходят в ваш чат по расписанию, панель восстанавливается из такого архива в пару нажатий.
* 🏰 **Щит** — защита от флуда и мусорных пакетов, каждый порог настраивается, плюс проверка защиты сервера с оценкой и советами.
* 🕒 **Часовой пояс сервера** — спрашивается один раз при установке и дальше меняется из меню: журналы, автообновления и бэкапы идут по вашему времени, а не по UTC.
* 🚪 **Безопасная смена SSH-портов** — старый порт закрывается только после того, как вы подтвердите вход через новый, поэтому случайно заблокировать себе доступ не получится.

## 📦 Компоненты Remnawave

| Компонент | Что разворачивается | Порт наружу |
| :--- | :--- | :--- |
| **Нода** | `remnawave/node` + `nginx:alpine` с сайтом-заглушкой, REALITY-ключи, изолированный сокет | `443` (+ `2096`, `8443` в схеме «Балансир») |
| **Панель** | `remnawave/backend:3` + `postgres:18.4` + `valkey` + nginx в host-сети | `443` |
| **Страница подписки** | `remnawave/subscription-page` + nginx | `443` |
| **Панель + Страница** | Всё вместе, один nginx на два домена по SNI | `443` |
| **Панель + Страница + Нода** | Всё на одном сервере: `443` держит Xray, остальное — за его unix-сокетом | `443` |

### 🔗 Как три компонента делят один порт

Раньше нода и панель не уживались на одной машине: обеим нужен `443` целиком. Теперь порт держит Xray, а всё остальное живёт за его unix-сокетом — там же, куда REALITY отдаёт непрошедший трафик.

```
:443  Xray ── REALITY ok ──> VLESS клиенты
           └─ не REALITY ──> unix-сокет (PROXY v2)
                                 домен ноды     → сайт-заглушка
                                 домен панели   → панель
                                 домен подписки → страница подписки
                                 прочий SNI     → рукопожатие обрывается
```

> [!IMPORTANT]
> В связке доступна только **шаблонная** схема ноды — балансиру нужны лишние публичные порты. Сертификаты выпускаются **раздельно**: свой у ноды, общий у панели со страницей. Один на все три домена положил бы имена панели в сертификат сайта-заглушки, и связь между ними стала бы видна снаружи.

### ☁️ Cloudflare: режим облака зависит от компонента

| Компонент | Режим записи |
| :--- | :--- |
| **Нода** | Только **DNS only** (серое облако) — REALITY не работает через прокси |
| **Панель, Страница подписки** | Рекомендуется **Proxied** (оранжевое облако) — прячет реальный IP сервера |

## 🐳 Нода Remnawave и схемы развертывания

Инструмент позволяет развернуть ноду Remnawave в один клик через интерактивный TUI-интерфейс, автоматически настраивая Docker, изолированные сокеты, SSL-сертификаты и безопасный доступ.

### 📋 Что понадобится для установки:
| Параметр | Описание |
| :--- | :--- |
| **Домен** | Доменное имя с **A-записью** на IP этого сервера (обязательно в режиме *DNS only*, если используется Cloudflare) |
| **IP панели** | Адрес вашего сервера с панелью Remnawave. В связке не спрашивается — панель рядом |
| **SECRET_KEY** | Секретный ключ ноды. В связке берётся из панели автоматически; при отдельной установке скрипт покажет инструкцию |

### ⚙️ Схемы развертывания:
| Схема | Порты | Как работает |
| :--- | :--- | :--- |
| **Шаблонная** | `443` | `selfsteal` TCP: Xray на 443, сайт-заглушка через Nginx |
| **Балансир** | `443`, `2096`, `8443` | `selfsteal` TCP + XHTTP + WS через Nginx, с выбором лучшего протокола по пингу (BEST). Трафик к сайту-заглушке ограничен по скорости (`limitFallback`), хосты получают Final mask с фрагментацией TLS ClientHello |

### 🔄 Мастер настройки и управления нодой (TUI)

| Компонент / Этап | Возможности и особенности |
| :--- | :--- |
| **Архитектура ноды** | Чистые переписанные `nginx.conf` и `docker-compose.yml`, отдельный сокет `/opt/remnanode/run`, легковесный `nginx:alpine`, TLS по профилю Mozilla, скрытый WebSocket-путь и лимит логов по 10 МБ |
| **SSL-сертификаты** | **HTTP-01** (с временным открытием 80 порта), **Cloudflare DNS** (wildcard по API-токену) или **ZeroSSL** — второй центр сертификации на случай, когда у Let's Encrypt кончился лимит. Перевыпуск без перезагрузки ноды |
| **Маскировка** | 171 шаблон сайтов из `website-templates` и 8 шаблонов `Mrvibecodic`; скачивается только выбранный вариант (обычно 1–3 МБ) |
| **Изоляция** | Контейнеры с `no-new-privileges`, монтируется только собственный сертификат ноды, а не весь `/etc/letsencrypt` |
| **Ctrl+C не ломает установку** | Случайное нажатие в мастере открывает экран «Пауза»: Enter — вернуться туда же, `y` — прервать |
| **Диагностика** | Умная сверка `target` в панели с сокетом ноды, проверка контейнеров (`remnanode` и `remnawave-nginx`), портов, UFW и автооткат при ошибках |
| **Администрирование** | Безопасный редактор конфигураций через `nano` с проверкой синтаксиса, смена ключей, перевыпуск сертификатов и пересоздание файлов без потери данных |

## 🧭 Панель Remnawave

Полный модуль: установка, обновление, бэкапы, диагностика и удаление — всё из меню.

| Возможность | Как работает |
| :--- | :--- |
| **Секретный адрес входа** | Панель открывается только по личной ссылке вида `https://домен/p-xxxxxxxx`, которая ставит cookie. Без неё домен отвечает `404` — боты и сканеры панель не найдут |
| **Закрытый API** | `/api/` доступен только с cookie или ключом `X-Api-Key`, `/api/sub/` открыт для клиентских подписок |
| **Администратор сам** | При установке заводится администратор со случайным логином и паролем, выпускается API-токен — логин с паролем показываются в конце |
| **Сброс администратора** | Забыли пароль — отдельный пункт: дамп базы, сброс учётки, новая со случайным паролем (или регистрация вручную в браузере) |
| **Бэкапы БД** | Дамп вручную, ежедневно в `04:20` по cron, восстановление из списка, ротация на 14 копий в `/var/backups/skipit`. Полный бэкап с отправкой в Telegram — [отдельный раздел](#-бэкап-в-telegram) |
| **Безопасное обновление** | Обязательный дамп базы до, ожидание healthcheck, при неудаче — откат образа и восстановление базы. Postgres закреплён и не обновляется |
| **Потолки памяти** | У каждого контейнера свой `mem_limit`, а у процессов Node — потолок кучи V8 по объёму RAM сервера. В образах зашито 16 ГБ, из-за чего на маленьких VPS раньше сборки мусора приезжал OOM-killer |
| **Сжатие и шаблон nginx** | В конфиг nginx добавлен gzip — фронтенд панели тянет WASM-модуль и бандлы на десятки мегабайт, без сжатия страница профилей открывалась минутами. Пункт «Пересоздать nginx.conf по шаблону SkipIt Tool» переносит правки шаблона на работающую панель без переустановки |
| **Шаблон Xray JSON «RU-Routing»** | Создаётся при регистрации первого администратора: `.ru`, `.su`, `.рф`, госсайты, банки и 500+ российских сервисов — напрямую и через DNS Яндекса, остальное — через DoH и балансир по пингу, Telegram — через прокси, торренты, IPv6 и QUIC на `443` — в блок. Подключается у хоста в поле «Шаблон Xray JSON»; отдельный пункт меню переписывает шаблон в любой момент |
| **Удаление** | С выбором: снести всё вместе с базой или оставить том с данными. Бэкапы не трогаются никогда |

## 🔗 Связки на одном сервере

### Панель + Страница подписки

* 🌐 **Один nginx на два домена** по SNI, страница ходит в панель по внутренней docker-сети — наружу торчит только `443`.
* 📜 **Один сертификат на оба домена** — вопрос о способе выпуска задаётся один раз: HTTP-01 или ZeroSSL со всеми доменами в SAN либо Cloudflare DNS на зону и `*.зона`.
* 🔑 **Токен выпускается автоматически** и сразу записывается в `sub.env`.
* ☁️ **Разные режимы Cloudflare** у доменов не проблема: на экране сертификата таблицей показано, какой домен за оранжевым облаком, какой напрямую и что это значит для HTTP-01.

### Панель + Страница подписки + Нода

* 📋 **Сначала вопросы, потом установка:** мастер спрашивает все три домена, порт ноды, сертификаты и сайт-заглушку сразу, показывает сводку — и дальше ставит всё сам, больше ничего не спрашивая.
* 🤖 **Нода заводится в панели сама:** мастер создаёт через API профиль конфигурации с ключами REALITY, саму ноду и хост Self-steal (TCP), а её инбаунд добавляет в Default-Squad — иначе хост не попал бы в подписки клиентов.
* 🔑 **SECRET_KEY не спрашивается** — берётся из панели через `/api/keygen`.
* 🧩 **Свой nginx панели не поднимается:** его работу берёт nginx ноды.
* 🧭 **Ставится в любом порядке:** мастер «всё на один сервер» с нуля, добавление ноды к работающей панели или панели к работающей ноде — переустанавливать ничего не нужно.

> [!NOTE]
> Переключение на связку защищено: Xray включается только когда панель отдаёт ему конфиг, поэтому скрипт ждёт, пока порт реально займётся, и при неудаче сам возвращает панели её nginx. В панель ничего не пишется до подтверждения установки.

Страницу подписки можно поставить и **отдельно** — с панелью на другом сервере. Тогда API-токен вводится руками и проверяется прямо при вводе: скрипт разбирает коды `404`, `401` и отсутствие связи и подсказывает, что не так.

## 💾 Бэкап в Telegram

Полный бэкап панели Remnawave приходит файлом в ваш Telegram-бот — по расписанию, которое задаёте вы.

| Возможность | Как работает |
| :--- | :--- |
| **Что внутри** | Дамп базы PostgreSQL — все пользователи, подписки, ноды, хосты и шаблоны; папка панели с `.env` и `docker-compose.yml`; страница подписки; сертификаты панели. Режим «Панель + весь сервер» добавляет ноду, сайт-заглушку, UFW, fail2ban и SSH |
| **Подключение бота** | Токен от @BotFather проверяется сразу, chat ID находится сам после `/start`, проверочное сообщение подтверждает связь |
| **Расписание** | Время первой отправки и интервал: каждый час, 3, 6, 12 часов, раз в сутки, раз в 2–3 дня или неделю — по часовому поясу сервера |
| **Сообщение** | Карточка SkipIt: сервер, версия Remnawave, число пользователей и нод, размер, время. Ошибки и выход новой версии SkipIt — отдельными сообщениями |
| **Восстановление** | Всё, только база или только файлы. Архив берётся с сервера, по пути или прямо из Telegram: перешлите файл боту — скрипт скачает его сам. Перед восстановлением сохраняются текущая база и папка панели |
| **Хранение** | По умолчанию архив удаляется с сервера сразу после отправки: при взломе VPS старые базы с токенами не достанутся, а при потере сервера копия останется в Telegram. Неотправленный архив не удаляется никогда |

> [!IMPORTANT]
> В архиве ключи, пароли и сертификаты — держите бота и чат закрытыми. Telegram позволяет боту отправить файл до 50 МБ и скачать до 20 МБ.

## 🏰 Щит — защита от DDoS и взлома

Своя цепочка правил в таблице `mangle` — раньше UFW и Docker. Уже открытые соединения, включая SSH-сессию, не затрагиваются. По умолчанию щит выключен: что включать и с какими порогами — решаете вы.

| Защита | Что делает |
| :--- | :--- |
| **Битые и поддельные пакеты** | Отбрасывает TCP-пакеты с невозможными флагами и пакеты вне соединений — ими сканируют и флудят |
| **Фрагменты** | Отбрасывает фрагментированные пакеты |
| **SYN-флуд** | Лимит новых TCP-соединений в секунду с одного IP и всплеск сверх него |
| **UDP-флуд** | То же для UDP — для нод с Hysteria2, TUIC или WireGuard |
| **Ping** | Лимит пингов в секунду |
| **Соединений с IP** | Потолок одновременных соединений с одного адреса (осторожно с CGNAT мобильных операторов) |
| **Защита ядра** | Защита от подмены адресов и ICMP-перенаправлений, SYN cookies, скрытие сведений о ядре — `/etc/sysctl.d/98-skipit-shield.conf` |

Плюс белый список IP, выбор портов для лимитов, шаблоны «мягкий / обычный / строгий» и статистика отброшенных пакетов. Правила переживают перезагрузку (`skipit-shield.service`); если ядро их не примет, вернутся прежние настройки.

> [!NOTE]
> Щит гасит флуд с отдельных адресов. Атаку, которая забивает весь канал сервера, может остановить только хостер — спросите у него про анти-DDoS защиту.

**Проверка защиты** ставит серверу оценку из 100: SSH (вход root, пароли, порт), UFW, fail2ban, щит, SYN cookies, автообновления, ожидание перезагрузки и открытые порты. Каждая проблема — пункт, который сразу открывает нужный раздел.

  | Профиль | Для чего |
  | :--- | :--- |
  | **fq + BBR** | большинство нод: точный темп отправки, минимум нагрузки на CPU |
  | **CAKE + BBR** | делит канал поровну между клиентами, CPU выше |
  | **Лёгкий** | серверы до 1 ГБ RAM: буферы до 8 МБ на соединение, память не уходит в своп |
  | **Дальние клиенты** | пинг 100+ мс и мобильные: буферы до 64 МБ, скорость держится после потерь |
  | **UDP** | Hysteria2, TUIC, WireGuard: большие буферы UDP, длинная очередь пакетов |

  Экран выбора сам советует профиль по объёму RAM сервера.
- **Безопасное управление параметрами**:  
  - Предустановленные профили оптимизации с предпросмотром.
  - Ручное редактирование через `nano` или полный сброс к дефолтным значениям системы.
- **Файл подкачки**: создаётся при установке, если его нет — страховка от OOM на маленьких VPS. Существующий swap не трогается, на Btrfs и ZFS шаг пропускается.
- **Часовой пояс сервера**: выбор из частых вариантов или поиск по названию города, подсказка по IP сервера, статус синхронизации времени. Контейнеры Remnawave остаются в UTC — их время от пояса хоста не зависит.
- **Управление IPv6**:  
  - Мониторинг статуса и адресов, включение и отключение, выбор основного протокола (IPv4 или IPv6).

### 🛡 2. Безопасность и Доступ
- **Тонкая настройка SSH**: Смена порта с проверкой через `sshd -t` и автооткатом при ошибках, управление `root`-доступом и паролями. Порт определяется по реальности: учитываются `ListenAddress` с указанным портом и сокет-активация systemd (`ssh.socket`) — в обоих случаях директива `Port` не действует, и раньше смена порта молча не срабатывала. После смены скрипт сверяет, что демон действительно отпустил старый порт.
- **Управление пользователями**: Создание аккаунтов, генерация паролей, выдача/отзыв прав `sudo`, безопасное удаление.
- **Импорт SSH-ключей**: Ручная вставка (`ed25519`/`rsa`), подтяжка с **GitHub** (`github.com/<user>.keys`), копирование из локальных файлов.
- **Интеллектуальный Fail2ban**: Защита от брутфорса, отслеживание рецидивистов и (по желанию) блокировка сканеров портов. IP текущей сессии добавляется в белый список только с вашего согласия — за NAT это открыло бы доступ соседям.
- **Автообновления безопасности**: `unattended-upgrades` в один пункт — ставятся только security-патчи, Docker исключён (чтобы контейнеры не перезапускались сами), перезагрузка не делается без спроса.
- **Проверка защиты**: оценка сервера по шкале из 100 — что уже в порядке, что нужно исправить и что стоит улучшить. Каждая проблема — пункт меню, который открывает место, где она исправляется.
- **Секреты не светятся**: Cloudflare-токен и GitHub PAT передаются через `curl -K -`, приватный ключ REALITY — через окружение, а не в аргументах команд, которые видны в `/proc`.

### 🧱 3. Сеть и Брандмауэр
- **Управление UFW**: Открытие/закрытие портов, просмотр правил, контроль статуса и IPv6. Закрытие порта SSH закрывает его и в `sshd`, чтобы «закрыт» не означало «закрыт только снаружи»; единственный порт SSH при этом не трогается. В таблице занятых портов рядом с каждым портом видно, что о нём думает UFW: «все адреса», «только с 172.18.0.0/16» или «закрыт в UFW».
- **Фильтрация трафика**: Блокировка IP-адресов и подсетей, настройка политик по умолчанию и сброс правил.
- **Общие ресурсы под присмотром**: При удалении компонента сертификат и порт `443` не трогаются, если они нужны другому — соседний компонент не сломается.

### 📊 4. Диагностика, Мониторинг и Утилиты
- **Диагностика компонентов**: Отдельные отчёты по ноде, панели и странице подписки плюс общий отчёт о готовности сервера. Проверки учитывают, что страница подписки отвечает только по ссылке с UUID, а в связке фронтом служит nginx ноды.
- **Понятные ошибки сертификатов**: если certbot отказал, показывается настоящая причина из лога: лимит на общий домен (`strangled.net` и т. п.), повторы одного набора имён или неудачные проверки — со временем снятия по часам сервера. При лимите Let's Encrypt скрипт сразу предлагает выпустить сертификат через ZeroSSL.
- **Главный экран**: состояние Remnawave, SSH, защиты, сети и системы цветными точками, загрузка CPU, RAM и диска, предупреждение, если хостер забирает процессор (steal).
- **Мониторинг (`btop`)**: Быстрый запуск системного монитора ресурсов.
- **Тесты и проверка сети**: Замер скорости через **Speedtest CLI (Ookla)** и проверка геопозиции IP (`ipregion`) по базам и сервисам (YouTube, Netflix, ChatGPT, Cloudflare). Оба инструмента скачиваются с проверкой `sha256`.
- **Обслуживание**: Безопасное обновление пакетов системы (с автоматической починкой загрузчика GRUB, если у VPS сменился диск), фоновая проверка обновлений скрипта и очистка диска (кэш apt, неиспользуемые Docker-образы, временные файлы SkipIt).

## 📋 Системные требования

| Параметр | Нода | Панель (или связка) | Всё на одном сервере |
| :--- | :--- | :--- | :--- |
| **ОС** | Debian 12 / Ubuntu 24.04 LTS | Debian 12 / Ubuntu 24.04 LTS | Debian 12 / Ubuntu 24.04 LTS |
| **Доступ** | `root` | `root` | `root` |
| **CPU** | 1 ядро (от него зависит скорость) | 1–2 ядра | 2 ядра |
| **RAM** | от 1 ГБ | от 2 ГБ | от 2 ГБ |
| **Диск** | от 10 ГБ | от 20 ГБ | от 20 ГБ |
| **Порты** | `443` свободен | `443` свободен | `443` свободен |
| **Домены** | 1, DNS only | 1 (панель) или 2 (со страницей подписки) | 3: панель, подписка, нода (DNS only) |

**Про процессор.** У ноды он главный ограничитель: Xray шифрует весь трафик, поэтому потолок скорости упирается в ядра, а не в канал. Панель наоборот — почти не нагружает CPU, ей важнее память.

**Про память.** Вхолостую стек панели со страницей подписки занимает около **700 МБ**: `remnawave` ~510 МБ, страница подписки ~120 МБ, Postgres ~56 МБ, Valkey ~11 МБ, nginx ~4 МБ. Запас в требованиях — на рост базы, пики при миграциях и обновлении. Каждому контейнеру выставлен `mem_limit`, а процессам Node — потолок кучи по объёму RAM, поэтому один разросшийся процесс не утянет сервер целиком.

Docker ставится автоматически официальным установщиком `get.docker.com`, если его ещё нет.

## ⚡ Быстрый запуск и обновление

Запустите команду в консоли вашего сервера от имени `root`:

```bash
curl -fsSL https://raw.githubusercontent.com/FrI3nd7/skipit-vps-node/main/skipit.sh -o /tmp/skipit.sh && bash /tmp/skipit.sh install
```

После установки и выбора часового пояса меню откроется само. Дальше инструмент открывается командой:

```bash
skipit
```

🔄 **Обновление на рабочем сервере:** через пункт **«Обновить SkipIt Tool»** в интерактивном меню `skipit` или выполнив команду `skipit update`.

- 🏷️ Новая версия берётся из последнего [релиза](https://github.com/FrI3nd7/skipit-vps-node/releases), а не из ветки `main`, и перед установкой сверяется с контрольной суммой.
- ✅ Обновление заменяет только сам скрипт: нода, панель, nginx, контейнеры и настройки сервера не меняются, прежняя версия сохраняется в `/var/backups/skipit/`.

🗑️ **Удаление** — пункт **«Удаление SkipIt Tool»** в меню, с выбором из двух вариантов:

| Вариант | Что уходит |
| :--- | :--- |
| **Только инструмент** | Команда `skipit`, `/etc/skipit`, задачи автобэкапа и бэкапа в Telegram, правила щита. Панель, нода и страница продолжают работать сами |
| **Всё** | Плюс компоненты, их папки, сеть docker и правило на `443`. Перед сносом базы делается дамп и остаётся на диске |

> [!NOTE]
> SSH и его правило UFW не трогаются ни в одном из вариантов — остаться без доступа к серверу хуже любого мусора в системе. Настройки ядра, `sshd` и fail2ban тоже остаются.

### 🧩 Все команды

| Команда | Что делает |
| :--- | :--- |
| `skipit` | Открыть меню |
| `skipit install` | Установить команду `skipit` в `/usr/local/bin` |
| `skipit update` | Обновить SkipIt Tool с GitHub (`--yes` — без вопросов) |
| `skipit uninstall` | Удалить команду (сервер и контейнеры не трогаются) |
| `skipit version` | Показать версию |

Служебные команды вызывают cron и systemd, вручную они не нужны: `skipit tg-backup` (бэкап в Telegram), `skipit panel-backup` (дамп базы панели), `skipit shield-apply` / `skipit shield-flush` (правила щита).
